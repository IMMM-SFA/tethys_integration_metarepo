# Data inventory

Every dataset this repository reads or writes, where it comes from, and which stage touches it. Compiled 2026-11-09 from the working tree, not from the other docs — see [Doc drift](#doc-drift) for the places they disagree.

Scope note: sizes are for a working copy with symlinks resolved. The repo tracks 13 data artifacts in git; everything else is fetched or regenerated.

`output/` is write-only from the repo's point of view. `test_config.yml` sets `output_dir: ./output/` and nothing reads it back — validation reads the adjusted output tree (`tethys_output_canonical` in `validation/paths.yml`) instead. Keep it a real directory rather than a symlink into a published dataset, or a rerun overwrites that dataset in place.

Grid and coverage are constant across everything below. CONUS at 1/8° (0.125°), bounds `[25.0625, 52.9375, -124.9375, -67.0625]`, six sectors (Domestic, Electricity, Irrigation, Livestock, Manufacturing, Mining), two use types (withdrawals, consumption), nine scenarios (`historical` plus `rcp{45,85}{cooler,hotter}_ssp{3,5}`).

### Stage 2 — runoff-share adjustment

`adjust_runoff_shares_method2_kazi.py` is canonical and produces the output tree named `output_adjusted_usgs_method2/`. It rewrites the per-sector GW/SW split from GCAM basin-level shares calibrated against USGS, constraining Electricity to surface water. `adjust_runoff_shares_hist.py` is the historical-only comparison variant.

## Units

Tethys and GCAM report km³/year; USGS reports MGD. Both conversion directions appear in the code, `km3_per_year_TO_mgd = 264172.05124 / 365` in the validation R scripts and `km3_in_one_million_gallons = 3.785412e-06` elsewhere. Validation scripts multiply USGS Domestic by 1.12 to match the public-supply-only definition introduced after 2015; `4a-compare-tethys-usgs.R` and `6-compute-table2-metrics.py` must agree on that factor.

### Avoiding a second input copy

`/rcfs/projects/im3/tethys/input/` already holds 43G in the category layout, covering all nine scenarios. `run_scenario_decep.py` reads it as `../../../../input`, which resolves there from the repo's location.

`link_data_layout.py` merges that tree in behind the flat scenario directories via `--fallback` (defaulting to `structured_input` for `$TETHYS_ENV`). Sources merge per destination filename and the flat directory wins, so a category can draw from both — the repo supplies the annual demeter years, the fallback the five-yearly ones the config actually requests.

With that in place, 22 byte-identical files (632 MB) and the 4.3G `database_rcp45cooler_ssp3` were removed from the repo's `data/historical` on deception, freeing 5.17G. What stays is what `input/` lacks: the power-plant proxy, `irrigation_weight_rcp45cooler.nc`, 12 annual demeter years, the HUC shapefiles, and `USGS-2025`.

Two layout mismatches to know about. The fallback keeps the demeter NetCDFs one level down in `demeter_78_PFT_output/`, so that rule needs a different source subdirectory than its destination. And `input/monthly/deficit` carries `updated_irrigation_weight_*`, a different and newer file than the repo's `irrigation_weight_*`, so both are linked under their own names and neither is aliased to the other.

### The rename

The rename broke four hard-coded paths. Rather than re-hard-coding the new name, `adjust_runoff_shares_method2_kazi.py` now resolves `--orig-root`, `--method2-root`, and `--usgs-baseline` from `scripts/3_config/paths.yml` under `$TETHYS_ENV`, defaulting to `pnl_rcfs`, each overridable on the command line. `tethys_run.sh` takes `$TETHYS_RUN_DIR`, defaulting to this repo's `scripts/1_runs/im3_tethys_runs`.

The rebuild deletes `--method2-root` and re-copies `--orig-root` over it. That is 33G, and with the path dead it had never actually fired. An existing tree now requires `--force`.

## Known rough edges

Left alone because fixing them changes results or repo structure rather than documentation.

- **Two scripts share the `5a-` prefix**, `5a-demand-sector-by-grid-cell.py` and `5a-paper-figures-save.R`.
- **`old/5c-scenarios-timeseries.R` and `old/5d-dominant-sector-map.py` still generate paper Figures 8 and 1.** Current deliverables living under `old/`. Promote them when stage-5 numbering is next cleaned up.
- **`run_scenario.py` cannot run locally.** It covers the eight futures, whose input data is not on the drive — only `historical/` is delivered. Its `scenario[:-5]` filename logic also yields `histo` for `historical`, so it was never meant for the historical case.
- **`data/` holds a stray `pixi.toml` and `pixi.lock`** that no documented environment references.
- **No interpreter on deception has `xarray`.** The `venv` and `venv_rocky` environments carry only mosartwmpy, and the `env-tethys` conda env that `tethys_run.sh` activates lives under `/people/niaz981/`. So stage 2 cannot actually run there yet regardless of paths. Its path resolution and guards are verified; the numerics are not.
